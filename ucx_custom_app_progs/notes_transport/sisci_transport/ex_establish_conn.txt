client server view. client is endpoint.

* server creates data interrupt

* client creates data interrupt

* client connects to server's data interrupt

* client triggers data interrupt at server, passes data like its own
  node ID, interrupt ID, and segment ID. + some other stuff that may not be used?
  (client then waits until it receives a data interrupt from server)

* data interrupt triggers callback on server (with data)

* server connects to data interrupt on client

* server triggers data interrupt with its segment with node_id, segment_id and other data
  (client wakes up)

* server connects to control segment on client, then maps it
  (client has run its own init func, so both server and client has a
   control segment with space for all the endpoints)

* Server disconnects data interrupt (then callback is done)

* Client stores data it received from server.

* Client disconnects remote data interrupt, i.e request interrupt (freeing it up for other endpoints)
* Client removes local interrupt, i.e. answer interrupt - because that is the interrupt the server used to answer

* Client uses information it received to connect to server's segment to connect to its receive segment


Key points:
    * SERVER connects to CLIENT's CONTROL segment, while...
      CLIENT connects to SERVER's RECEIVE segment
