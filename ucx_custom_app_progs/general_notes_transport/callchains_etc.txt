Details:
	- uct_sci_ep_am_short is sent a lot since UCX wants to make sure it benchmarks things correctly (apparently)
	
	- uct_sci_iface_query for active messages a cpu is basically just spin waiting by calling this function.
	  it is therefore called all the time, more often than uct_sci_ep_am_short.
	  It is used to check whether a message has been sent yet.
	  Takes up an entire CPU throughout the sending of a message basically, to ensure low latency (low latency vs CPU usage tradeoff)
	  This might just be because the performance program wants to test the latency though. A typical program might do some work in this period instead.
	  
	- uct_sci_ep_am_short Does periodic checks. Checks bandwidth, message size, health status etc (if implemented to support this I assume).
